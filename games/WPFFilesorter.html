WPF File sorter

In the past I used to sort my downloaded files using a Batch script, I chose to re-create this tool with more advanced and user-friendly features as a way to learn .NET, specifically WPF.
This re-created version of the app sorts files like the old version, but now the user can also change paths and set up rulesets within the app itself.

View the full project on Github

About the project

From the main view of the app, the user can enter the settings and profiles menu to adjust settings and change the sorting ruleset.

The main view of the app.

Clicking the Sort button starts the sorting process according to the rules set by the user, the sorted files and their destinations will be displayed in the info field.

The sorter displays the changes it makes during the sorting process.

Changing rulesets

The ruleset is managed in the Profiles menu, here the user can add, edit and remove rules.
When the user adds a new rule, they can fill in the name of the target folder and add a list of file extensions that belong in that target folder.

The Profiles view.

The profiles menu also has an export and import function, a ruleset can be saved as a JSON file to easily store or transfer them.

Code sample: MVVM pattern

When researching how to switch between different views/menus, multiple sources recommended or discussed implementing a MVVM design pattern.
This design pattern is mostly meant for larger applications that have a lot of different views/menus, in the code this pattern makes it easier to switch between views and manage the state the app is in.
Even though the sorting app is not that large with 3 different menus, I wanted to implement this system for potential future additions and to understand the system better.

In a Model-View-ViewModel pattern every window/menu has its own ViewModel script that links the visual menu and the underlying logic together.
This script is the Root viewmodel, it is the only one that does not have a menu linked to it, instead this viewmodel manages the other viewmodels by creating and storing them.
The root viewmodel is also responsible for switching between menus and tracking which menu is being viewed, a single script managing this functionality makes the app more stable and easier to manage. 


using FileSorter.Rule_system;

namespace FileSorter.ViewModels
{
    public class RootViewModel : ViewModelBase
    {
        private readonly ISorter _sorter;
        private readonly RuleService _ruleService = new RuleService();

        public ViewModelBase CurrentViewModel { get; private set; }

        private MainViewModel _mainVm;
        private SettingsViewModel _settingsVm;
        private ProfilesViewModel _profilesVm;

        public RootViewModel()
        {
            if (_sorter == null)
            {
                _sorter = new Sorter(_ruleService);
            }
            _ruleService.Load();
            ShowMain();
        }

        private void ShowMain()
        {
            _mainVm ??= new MainViewModel(
                _sorter,
                ShowSettings,
                ShowProfiles);

            CurrentViewModel = _mainVm;
            OnPropertyChanged(nameof(CurrentViewModel));
        }

        private void ShowSettings()
        {
            _settingsVm ??= new SettingsViewModel(ShowMain);
            CurrentViewModel = _settingsVm;
            OnPropertyChanged(nameof(CurrentViewModel));
        }

        private void ShowProfiles()
        {
            _profilesVm ??= new ProfilesViewModel(_ruleService, ShowMain);
            CurrentViewModel = _profilesVm;
            OnPropertyChanged(nameof(CurrentViewModel));
        }
    }
}
